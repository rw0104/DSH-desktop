更新时间：2026-08-24

> 执行状态（2026-08-24）：BASE/VIS-0/VIS-1/VIS-2（移除分支）/NAV/UPD-1/ART-1/ART-2/UPD-2 的实现和 headless/unsigned packaged smoke 已完成；MOD-3 的 Host/Adapter/目录/第三方 paste 全矩阵、ART-3 UI 行为覆盖、UPD-3 的 updater 运行时发布者锁定、正式签名安装器及 REL-1 的干净 Windows 安装/覆盖/卸载/回滚仍未完成。候选版本说明见 [`releases/v2.0.9.md`](releases/v2.0.9.md)。

## 目标和发布原则

本计划把 [`2026-08-24_analysis-v2.0.8-update-startup-vision-report.md`](2026-08-24_analysis-v2.0.8-update-startup-vision-report.md) 的结论转换为可独立验收的工作包，覆盖：

- 更新体验和安装器来源验证；
- 启动时外部网页的阻断、归因和测试；
- 第三方视觉工具的打包缺件、默认接管和可禁用治理；
- 视觉模型能力设置、元数据刷新和模型切换；
- 对话产物复制绝对路径和文本内容；
- 打包烟测和发布门禁。

发布原则：

1. `v2.0.9` 优先成为可信的修复版本，不继续堆功能。
2. 当前 Vision Toolkit 成品不可用且不可禁用，属于发布阻断项。
3. 当前更新器不得在没有 SHA-256/签名结论的情况下升级为静默自动安装。
4. 不通过取消图片安全门禁解决视觉误判。
5. `deepseek-harness/` 保持只读固定子模块；需要修改官方模型设置、API 合约或 Deliverables UI 的工作先走官方上游贡献和发布，再单独更新 submodule pin/package family。
6. 每个工作包先写能命中真实故障面的测试，再修改实现。

## 对话产物复制

### ART-1 Host 安全契约

架构决策先行：产物行由官方 `ui-deliverables` 拥有，完整兼容模式最好走官方上游合约；Desktop 可以提供 Electron clipboard adapter，但不能在兼容模式用 DOM patch 偷换上游组件。

建议请求：

```typescript
type DeliverableCopyRequest = {
  sessionId: string
  path: string
  kind: 'absolute-path' | 'text-content'
}
```

Host 不相信 Renderer 的 path。它必须确认该 path 属于指定会话已经派生出的 deliverables 集合，再解析实际文件。

任务：

1. 将相对产物路径绑定到会话 workspace/cwd；绝对路径也必须落在允许根中。
2. 拒绝 NUL、空路径、目录、设备、socket、越界、符号链接和 junction/reparse 越界。
3. 使用规范化/真实路径 containment，Windows 比较大小写不敏感并正确处理盘符根。
4. `text-content`：regular file、最大 1 MiB、limit+1 有界读取、UTF-8 fatal、NUL 拒绝。
5. 读取和复制之间处理文件替换竞态；能使用已打开 handle 的 stat/realpath 事实，不用两次裸路径检查。
6. 返回稳定错误码：`not-produced`、`outside-workspace`、`not-file`、`linked-path`、`too-large`、`binary`、`changed`、`unavailable`。
7. Electron clipboard 只接收已经通过 Host 校验的字符串；不把任意主机文件读取能力暴露给 Renderer。

建议首版大小上限固定为 1 MiB。后续如需更大内容，应改为“打开文件/导出”，而不是无限复制到剪贴板。

### ART-3 测试矩阵

| 类别 | 用例 |
| --- | --- |
| 正常 | 相对文本、绝对文本、空文本、恰好 1 MiB、Windows `C:\` workspace |
| 路径 | `..`、不同盘、UNC、盘符大小写、前缀碰撞 `C:\work`/`C:\workspace2` |
| 链接 | 文件 symlink、父目录 symlink、junction/reparse、检查后替换 |
| 类型 | 目录、FIFO/socket（非 Windows fixture）、设备、二进制、NUL、非法 UTF-8 |
| 大小 | 1 MiB+1、伪造小 stat 后增长、读取中变化 |
| 授权 | 不是该 turn 产物、不是该 session、旧 session、Renderer 伪造绝对路径 |
| UI | 两个动作、loading 去重、成功 toast、错误映射、键盘/读屏、剪贴板拒绝 |

验收：所有失败均不把文件内容或 Host 绝对路径泄漏到网络/日志；没有任意文件读取原语。

## 后台更新与签名

### UPD-2 成熟更新体验

在 UPD-1 可信清单完成后：

1. 下载到 `%APPDATA%/DSH Desktop/updates/<version>/` 私有目录，不再让用户每次选择保存位置。
2. 更新状态机：idle → checking → available → downloading → ready → installing/failed。
3. UI 展示版本、发布说明入口、大小、进度、重试、现在重启/稍后。
4. 用户工作进行中不强制退出；正常退出时可选择安装。
5. 新版本启动后询问删除旧安装器，失败自动清理 partial，保留最近一次可重试资产。
6. 网页手动下载只在自动更新不可用时出现。

差分包不是 v2.1.0 必需项。先把完整安装包做正确，再评估 electron-updater differential blockmap。

### UPD-3 Authenticode

1. CI 使用受保护的代码签名凭据签名 EXE 和安装器。
2. release verifier 执行签名链、时间戳和发布者名称校验。
3. updater 锁定预期 publisher；签名缺失、过期、名称变化或校验失败时拒绝执行。
4. 发布说明记录签名状态和 SHA-256，不记录证书私钥信息。
5. 评估 `electron-updater` 的 NSIS 能力；采用时保留现有取消、状态清理和用户确认语义。

验收：候选安装器在干净 Windows 主机显示预期发布者；篡改一个字节后 SHA 和签名校验都失败。

## REL-1 发布门禁

进入发布候选前按顺序执行：

1. 依照 `docs/upstream-sync.md` 记录三条权威 remote、npm package family、Vision Toolkit 版本和兼容性结论。
2. `corepack yarn install --immutable`。
3. 聚焦红绿测试：Vision closure、external navigation、update manifest、model capability、deliverable copy。
4. `corepack yarn typecheck`。
5. `corepack yarn check`。
6. Windows packaged smoke：真实 app.asar 自检、Profile/Loader、Renderer 启动、零自动外链、目录选择器、视觉矩阵。
7. 安装器 verifier：PE、SHA-256、Authenticode、版本资源、安装/覆盖/卸载/重启安装。
8. 使用隔离 `DSH_HOME/userData` 做升级烟测，完成后删除临时目录，不在仓库保留重复 `win-unpacked` 或安装器副本。
9. 发布说明列出已修复、明确未修复、回滚点、安装器大小/SHA/签名状态。

发布阻断条件：

- 任一默认产品 Bundle 自检失败；
- 启动无用户操作却调用 `shell.openExternal`；
- 更新安装器没有匹配 SHA-256，或要求签名的渠道签名不匹配；
- 原生视觉模型触发第三方视觉网络请求；
- Vision Toolkit 仍不可禁用；
- 产物内容复制能读取未授权路径、超限或二进制；
- 根 README 产品身份被上游内容替换；
- `deepseek-harness/` 有未单独提交或未经上游发布的源码修改。

## 提交与交付顺序

建议保持以下独立提交，避免把修复变量混在一起：

1. `test(desktop): reproduce packaged vision and update trust failures`
2. `fix(desktop): make optional vision bundle disableable`
3. `fix(package): verify product bundle runtime manifests`
4. `fix(security): require trusted update artifact metadata`
5. `fix(desktop): restrict external navigation to explicit actions`
6. 上游 Harness PR：模型能力设置/投影/刷新（不在 Desktop 子模块内提交）
7. 独立 submodule pin 更新提交
8. `feat(deliverables): add bounded copy actions`（上游或已审查的 Desktop 组合边界）
9. `test(release): gate packaged vision, navigation, updates, and copy`
10. `docs(release): record v2.0.9 verification and remaining work`

每次重大方向变化前提交当前阶段；submodule pin 更新与 Desktop 行为变化保持分离。

## 完成定义

只有同时满足以下条件，才能关闭本计划：

- 用户从 v2.0.8 可以在应用内可信地升级，无需手动浏览发布页；
- 启动不会无操作打开系统浏览器，所有外链可归因；
- 第三方视觉工具可禁用、默认不接管、打包后自检通过，或已从产品中移除；
- 真实视觉模型能通过显式能力声明走原生图片链，纯文本模型仍被安全拒绝；
- 模型设置提交、能力刷新、模型切换和图片发送没有旧状态竞态；
- 产物可以复制 Host 解析的绝对路径，并可在严格范围/大小/文本校验后复制内容；
- Headless gate、packaged smoke、安装器校验和升级回滚全部通过；
- 发布说明和同步台账与实际产物一致。
