# DSH Desktop v2.2.2

修复 2.2.1 实时语音按钮“已启用但点击无响应”的问题，保留图片输入自动识别。运行时依赖版本不变。

## 为什么点击没有反应

RC1 的会话插槽通过顶层 `sessionId` 提供会话身份，Desktop 按钮却读取已不存在的 `session.sessionId`。异常发生在点击事件中，早于打开语音面板和请求票据，因此界面启动健康、按钮也可用，但点击不能启动语音。

按钮现在使用上游 `SessionStandardProps` 的会话字段，本地错误的 slot owner 声明已删除。新增回归实际执行点击，验证面板打开、正确会话的票据请求，以及服务端拒绝时的错误反馈。此前只检查按钮是否灰显，未覆盖点击，不能作为功能正常的证据。

实际浏览器点击进一步暴露兼容界面没有 Workbench 语音标签出口的问题。兼容模式现在通过上游公开的 `shell.overlay` 插槽显示独立语音对话框，不替换上游根布局；高级模式继续使用侧栏。关闭或按 Escape 会释放麦克风，并取消尚未完成的启动，避免关闭后才弹出麦克风请求。

连接失败的清理改用浏览器允许的应用关闭码 `4001`，不再用禁止从浏览器发送的 `1011`，避免原始错误被第二个异常掩盖。

## 图片输入与生图的区别

当前聊天模型支持文本或图片输入，主要适配器输出仍为文本。图片输入自动识别不意味着接入了生图接口；仅添加生图模型 ID 或勾选图片输入不能获得图片输出。生图需要另行接入供应商的生成/编辑接口、参数、图片下载和结果展示。

## 验收边界

点击和连接流程测试与真实服务商音频通话是不同证据。模拟服务端及假麦克风不验证用户设备、供应商授权或真实语音质量；不能据此宣称全部实时语音功能已经完成实机验收。
