# DSH Desktop v2.0.3

发布日期：2026-08-20

## 必须升级

`v2.0.2` 的 Desktop Client 错误地把已经从 rc8 组合中移除的 `betterSidebar` service 声明为必需 injection。即使是全新机器，也可能在 Host 启动后等待 Renderer health 30 秒并闪退。本版本移除该错误依赖并恢复正常界面启动。

已经卡在 `v2.0.2` 恢复窗口或闪退的用户，需要手动安装一次 `v2.0.3` Setup。该版本无法存活到后台更新检查开始，因此不能依靠自身自动修复。安装 `v2.0.3` 后，后续 Windows 稳定版本会继续自动检查本仓库的 GitHub Release，并在用户确认后下载和启动 Setup，不需要每次手动访问 GitHub。

## 修复内容

- Desktop Client 不再要求 `betterSidebar` service；当可选 sidebar registry 不存在时，主界面仍能健康启动，Changes tab 只是不注册到该扩展面板。
- 启动时迁移历史 desktop profile，从 bundle 加载清单移除 `@anionex/dsh-vision-toolkit` 与 `dsh-better-sidebar`，避免旧版升级用户先进入无法解析 bundle 的恢复循环。
- 迁移只修改 profile 的 bundle 清单，不删除插件文件、依赖声明、设置、凭据、会话或工作区；其他第三方 bundle 的顺序保持不变。
- 保留 `v2.0.2` 建立的产品自有更新通道：GitHub latest stable Release 检测、精确 tag Setup 下载、PE 校验、原生保存对话框、确认后重启安装和安装包清理提示。

## 受影响范围

| 场景 | v2.0.2 | v2.0.3 |
| --- | --- | --- |
| 全新 Windows 安装 | 可能 Renderer 超时闪退 | 不依赖 Better Sidebar，可正常启动 |
| 从 v1.x 升级且保留 Vision/Better Sidebar | profile composition 失败或恢复后闪退 | 自动迁移旧 bundle 清单后启动 |
| 后续稳定版本更新 | 应用闪退时无法等到后台检查 | 后台检查或托盘手动检查，确认后自动下载 Setup |

## 升级方法

1. 退出 `v2.0.2` 或关闭恢复窗口。
2. 打开 [v2.0.3 Release](https://github.com/rw0104/DSH-desktop/releases/tag/v2.0.3)。
3. 下载并运行 `DSH-Desktop-2.0.3-x64-Setup.exe` 覆盖安装。
4. 启动后在设置的 **关于** 页面确认版本为 `v2.0.3`。
5. 保留现有 `%APPDATA%\DSH Desktop` 与 DSH home；迁移会在首次启动时处理旧 bundle 清单。

## 产物与限制

- Windows Release 产物为 `DSH-Desktop-2.0.3-x64-Setup.exe` 与 `latest.yml`。
- GitHub Setup：`209,554,846` bytes，SHA-256 `c265b0ec9138f3a7e5d005c2219e6854837f11a5be45c7f876686edaaac67c93`。
- 当前下游仍未发布签名、公证后的 macOS DMG；macOS 只报告新版本，不提供下载。
- Windows Setup 尚未 Authenticode 签名，可能显示 SmartScreen 或 Unknown Publisher。
- `v2.0.2` 闪退用户的一次手动覆盖安装无法由已经崩溃的旧进程自动完成；从 `v2.0.3` 开始恢复正常自动更新链路。
