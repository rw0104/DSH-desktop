# DSH Desktop 2.2.9 更新说明

2.2.9 修复历史 Profile 依赖投影把已安装应用连接到开发目录、其他版本或失效目录后，造成核心包混用、Zod/codec 注册失败和启动异常的问题。本版同时包含此前 2.2.8 本地测试中的 Harness 接入及完整桌面体验改进。

**Windows x64 正式版**：[Release 页面](https://github.com/rw0104/DSH-desktop/releases/tag/v2.2.9) · [下载安装器](https://github.com/rw0104/DSH-desktop/releases/download/v2.2.9/DSH-Desktop-2.2.9-x64-Setup.exe)。安装器未进行 Authenticode 签名，Windows 可能显示 Unknown Publisher / SmartScreen 提示。本次不发布 macOS 或 Linux 原生包。

本版内置官方 Harness **0.1.6-alpha.2** 发布族与维护中的 Better Sidebar **0.19.1**。这是 DSH Desktop 的正式版本，**不表示上游 Harness 已从 alpha 转为稳定版**。第三方插件需要兼容该内核；插件市场收录不构成兼容性保证。

## 升级与回退

1. 完全退出应用，包括托盘中的后台进程，再备份完整 Harness home、Electron 用户数据及工作区。Windows 默认目录是 `%USERPROFILE%\.dsh` 和 `%APPDATA%\DSH Desktop`；使用自定义路径时以实际启动配置为准。
2. 安装并运行 2.2.9。新解析方式忽略共享 Profile 中的历史运行时投影，不通过删除或重建整个用户依赖目录完成修复。用户插件、凭据、设置及会话继续保留；第三方插件与新内核不兼容时仍需单独更新。
3. 若要回退，将升级前的完整备份恢复到独立目录，并由匹配的旧版本使用。不要让旧程序直接复用升级后的数据目录，也不要把升级后新增的会话记录自动合并回旧格式。

**本版不自动备份、清除历史链接或执行版本回滚。** 旧版本可执行文件不包含这次解析修复，重新安装旧版也不会清除用户 Profile 中的历史依赖关系。保留旧会话格式原件不等于任意旧程序都能安全使用升级目录；回退必须保留新目录与升级前备份各自的完整性。

## Profile 运行时隔离修复

此前，安装目录中的 EXE、ASAR 即使没有变化，共享 `profiles/node_modules` 中指向开发 checkout 的链接也可能让应用加载另一套核心包。开发目录升级或被清理后，旧应用会随之混版或缺包；降级主程序不能独自恢复这部分状态。

2.2.9 调整了整个加载路径：

- 内置核心和插件以当前安装为解析锚点，完整内核发布族随应用交付，避免从共享 Profile 投影选择另一版本的内置包。
- 使用官方进程内 Profile resolution generation；Host 启动和 Client 模块发现不再向共享 Profile 依赖目录创建、更新或修复链接，也不把开发 checkout 投影到用户运行时。
- 第三方插件只有在当前选定的 Profile 中真实安装后才作为本地入口加载。真实插件的私有依赖保留自身解析语义，缺失的共享依赖才从当前安装解析；历史 fallback 占位不冒充已安装插件。
- 旧版、新版、断裂的共享投影不再决定新版本的内置插件加载。修复不遍历并删除用户依赖，不删除未知会话以隐藏错误。

这项修复消除的是历史共享投影造成的版本混用。它不自动修改第三方插件的 API 或其私有依赖，也不承诺所有旧插件都可直接用于新内核。

## 相对 2.2.7 的桌面改进

- **完整日常桌面**：系统窗口与原生桌面外观提供相同的添加菜单、文件上传、图片保存、语音浮窗和小型控制条；窗口外观与 Agent 工具预设分别设置。
- **多会话工作台**：适配 Harness 的会话与标签页接口，保持同一会话的引用共享、不同会话的草稿隔离，以及标签页打开、关闭、释放与恢复的归属。
- **插件管理**：接入官方运行时插件管理服务，保留 Desktop 安装恢复记录和重启健康确认；上游诊断体验的插件控制只读，不消费日常 Profile 的安装恢复事务。
- **现有能力继续接入**：原生图片生成与预览、模型能力发现、工作区文件上传、交付物保存、Windows 目录选择与受限执行、CLI 及 Sidebar 适配随新内核一并保留。

Qwen 原生语音 Agent 继续标为实验功能。模型、图片和音频的实际可用性仍取决于供应商接口、账号权限及所选模型。上游原始界面作为显式诊断入口，不替代日常桌面的功能组合。

## 开发与测试隔离

`corepack yarn dev` 和 `corepack yarn start` 在构建或启动前先只读审计真实 Profile 是否引用当前 checkout；随后为这次开发运行创建独立的 Harness home、Electron user-data、临时目录和工作目录。`dev` 先构建，`start` 使用已有构建。开发运行的数据在最终退出后清理，不用于持久保存日常会话。

修改运行时代码、依赖或清理构建目录前，使用以下只读检查；自定义 home 加上 `--home <绝对路径>`：

```sh
corepack yarn check:runtime-boundary
```

发现真实 Profile 指向即将修改的 checkout 或临时打包树时，必须先停止影响该目标的变更，并制定独立恢复方案。测试和一次性冒烟通过 `scripts/run-isolated-check.mjs` 设置隔离环境；更换工作目录本身不能隔离会话存储。真实安装目录、用户数据、凭据与恢复状态不属于开发清理范围。
