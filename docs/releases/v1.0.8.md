# DSH Desktop v1.0.8

状态：开发记录；本计划版本已并入 `v2.0.2`，不再创建 `v1.0.8` 标签

> 桌面上游同步后产品基线已进入 2.x。本页保留 W3.2 的阶段证据，正式升级、验证与产物以 [v2.0.2](v2.0.2.md) 为准。

## 用户可见变化

- 插件市场：设置中新增 Desktop-owned 插件市场，可查看受信任目录、安装/删除插件，并在操作后请求重启加载新 profile 组合。
- 日志：Electron 用户数据目录新增 UTF-8 日志：Windows 为 `%APPDATA%\\DSH Desktop\\logs\\dsh-desktop.log`，macOS 为 `~/Library/Application Support/DSH Desktop/logs/dsh-desktop.log`；日志最多保留当前文件约 5 MiB，并轮转一个 `.1` 文件。
- 恢复助手：托盘新增恢复助手。每次成功启动后保存当前 profile manifest 快照；启动失败时尝试恢复最后健康快照。恢复助手不修改环境文件、用户工作区或 pinned upstream。
- 侧边栏目录：鼠标悬停文件树目录时出现“在系统文件管理器中打开”按钮；Host 校验 Session 绑定路径后调用原生文件管理器。
- Workspace Workbench W3.2：可在固定 managed root 下创建 Host-owned Git worktree，并安全回收 clean worktree；dirty、unmanaged、owner/path 不匹配的回收会被拒绝。

## 升级与限制

- 当前功能尚未创建 `v1.0.8` 标签或安装包；正式发布前必须重新运行 Windows package gate、打包版 UI smoke，并将 GitHub Release 正文链接回本文。
- 插件安装/删除只允许固定目录条目，不接受 Renderer 任意包名；变更需要重启。
- 恢复助手只恢复 profile `package.json` 快照，不能修复插件直接修改系统环境文件、用户工作区或外部 Python 环境造成的问题。
- W3.2 managed worktree 创建/回收已完成；W3.3 setup script/environment 和 W3.4 handoff/UI 尚未完成。

## W3.2 Worktree/Environment

- `WorkspaceWorktreeService` 提供固定 managed root 下的 Host-owned create/remove；source checkout 必须 clean，branch 按 Git ref 规则校验，已存在 branch、dirty worktree、unmanaged checkout 和 owner/path 不匹配均返回稳定错误码。
- `/dsh-desktop/api/workspace/worktrees` 保留 GET inspect，并增加带 `x-dsh-workbench-action: worktrees` 的 Session-scoped create/remove action；repository root 始终取自 Host binding。
- 覆盖真实 Git fixture、branch conflict、dirty refusal、unmanaged refusal、route owner/path authority 和 structured argv。

W3.2 验证结果：`check:win-package` 通过，19 个测试文件共 191 passed、1 skipped；runtime closure 197 first-party nodes 通过。当前未创建 v1.0.8 标签、安装包或 GitHub Release。
