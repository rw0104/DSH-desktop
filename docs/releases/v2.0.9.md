# DSH Desktop v2.0.9（候选）

> 状态：Desktop 基础修复候选已完成，完整计划和正式发布尚未完成。MOD-3 全矩阵、UPD-3 updater 发布者锁定、Windows Authenticode 证书以及干净主机安装/覆盖升级/卸载/回滚仍是发布前门禁；本文件不把 unsigned 构建当作可下载 Release。

## 本轮修复

- 原生视觉模型能力不再依赖第三方视觉工具：模型设置支持明确声明 `text`/`image`，能力字段贯穿 Host catalog、Adapter、会话目录和模型选择器；未声明或 unknown 的模型继续安全拒绝图片。
- Vision Toolkit 不再是默认、不可禁用或直接产品依赖。用户显式安装时才参与 Profile；原生 `image` 模型优先官方附件链，不把图片静默外发给第三方服务。
- 对显式启用的第三方 Bundle 增加 manifest 文件、大小和 SHA-256 完整性检查；缺 `CHANGELOG.md` 等成品缺件会在打包阶段失败，而不是启动后误报 API Key/环境问题。
- 修复 Desktop web-runtime 覆盖层遗漏 `openBrowser` 导致的启动网页；任意 Renderer 新窗口默认拒绝，仓库和 Release Notes 只通过固定、可审计的外链 action 打开。
- 更新器消费 Release 资产的精确版本/文件名/大小/SHA-256，下载到应用私有目录并在重启安装前再次确认；失败通过原生对话框反馈，避免把用户带到网页手动下载。
- 新增对话产物“复制绝对路径”和“复制文本内容”：只接受当前会话已证明的产物，限制 workspace/cwd 范围、拒绝符号链接/junction/目录/设备/二进制/NUL/非法 UTF-8，并将文本限制为 1 MiB。
- Windows Release workflow 禁止覆盖同名资产，回读 GitHub Release digest/size，并要求证书、签名和 `/pa /all` 验证全部通过后才允许发布。

## 明确不做的事

- 不取消 Host/Adapter 的图片能力安全门禁，也不根据模型名称猜测视觉能力。
- 不把 Vision Toolkit 作为主体 Agent 的权限层；它是可选输入增强插件，不能越过 Host 路径和模型能力边界。
- 不承诺 v2.0.8 用户无需一次覆盖安装即可获得 v2.0.9 的修复；无法启动的旧版本只能通过一次手动安装进入新更新链。
- 不在没有签名证书、资产 SHA-256 和干净 Windows 安装验证时发布安装器。

## 发布前待办

1. 补齐 MOD-3/ART-3：原生视觉、text-only、unknown、切换/刷新竞态、第三方 paste policy，以及复制 UI 的键盘/读屏/loading/错误映射测试。
2. 在更新下载前增加 Windows Authenticode 链、时间戳和固定 publisher 指纹校验；签名缺失、过期或发布者变化必须拒绝。
3. 在受控 CI 注入 `WINDOWS_SIGNING_CERTIFICATE_BASE64`、`WINDOWS_SIGNING_CERTIFICATE_PASSWORD` 和发布者指纹，完成 Authenticode 及 `/pa /all` 验证。
4. 生成唯一的 `DSH-Desktop-2.0.9-x64-Setup.exe`，记录文件大小、SHA-256、签名主题/指纹；禁止复用或 clobber 已上传资产。
5. 在干净 Windows 主机完成安装、覆盖升级、卸载、重启安装和失败回滚；隔离 `DSH_HOME/userData` 测试后清理临时目录。
6. 确认原生 `image` 模型的第三方视觉服务请求数为 0，text-only/unknown 模型的图片请求在 Host/Adapter 两层均被拒绝。
