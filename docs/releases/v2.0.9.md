# DSH Desktop v2.0.9

> Windows 安装包延续 v2.0.8 的透明 unsigned 发布策略：GitHub Release 校验资产大小和 SHA-256，并由用户确认后安装；由于仓库尚未配置受信代码签名证书，Windows 会显示 Unknown Publisher。Release workflow 会在文末自动追加最终安装器大小、SHA-256 和 Authenticode 状态。

## 本轮修复

- 原生视觉模型能力不再依赖第三方视觉工具：模型设置支持明确声明 `text`/`image`，能力字段贯穿 Host catalog、Adapter、会话目录和模型选择器；未声明或 unknown 的模型继续安全拒绝图片。
- Vision Toolkit 从正式产品、Profile 依赖、安装包和设置入口彻底移除；原生 `image` 模型只走官方附件链，不再提供第三方视觉外发路径。
- 官方 packaged verifier 拒绝已移除 Vision Toolkit 的任何 ASAR 残留；v2.0.8 的 `CHANGELOG.md` 缺件不会再进入 v2.0.9 成品，也不会在启动后误报 API Key/环境问题。
- 修复 Desktop web-runtime 覆盖层遗漏 `openBrowser` 导致的启动网页；任意 Renderer 新窗口默认拒绝，仓库和 Release Notes 只通过固定、可审计的外链 action 打开。
- 更新器消费 Release 资产的精确版本/文件名/大小/SHA-256，下载到应用私有目录并在重启安装前再次确认；失败通过原生对话框反馈，避免把用户带到网页手动下载。
- 新增对话产物“复制绝对路径”和“复制文本内容”：只接受当前会话已证明的产物，限制 workspace/cwd 范围、拒绝符号链接/junction/目录/设备/二进制/NUL/非法 UTF-8，并将文本限制为 1 MiB。
- Windows Release workflow 禁止覆盖同名资产并回读 GitHub Release digest/size；配置代码签名证书时要求 `/pa /all` 通过，没有证书时必须显式验证并披露 `NotSigned`。

## 明确不做的事

- 不取消 Host/Adapter 的图片能力安全门禁，也不根据模型名称猜测视觉能力。
- 不把 Vision Toolkit 作为主体 Agent 的权限层；v2.0.9 不再加载该插件，历史 Profile 只做安全清理，不恢复它。
- 无法正常启动或无法进入更新检查的旧版本仍需手动覆盖安装一次；可正常运行的 v2.0.8 可以通过应用内更新链下载 v2.0.9。
- 不把 SHA-256 校验描述为 Authenticode；本版发布者状态如实记录为 `NotSigned`。

## 已知限制与后续工作

1. 后续配置受信 Windows 代码签名证书，并在 updater 中锁定发布者链和时间戳；签名渠道完成后不再接受 unsigned 安装器。
2. 继续扩充产物复制 UI 的键盘、读屏、loading 和错误映射自动化覆盖。
3. Vision Toolkit 已彻底移除，不再把第三方 paste policy 作为正式产品测试矩阵；原生 image/text-only/unknown 仍由 Host 和 Adapter 双门禁覆盖。
