# DSH Desktop v2.0.16

> 发布门禁状态：本地打包、安装和真实 Renderer 验收已通过；版本化 Windows 性能 workflow、长路径计时和失败恢复仍是发布前门禁。

DSH Desktop v2.0.16 将 Windows 安装目录从“完整 ASAR 物理镜像”改为消费者驱动的运行时闭包，并把文件数、展开体积、安装耗时和混合版本恢复固化为发布硬门禁。

## 主要更新

- Electron Main/Renderer 可直接读取的模块只保留在 `app.asar`；普通文件层仅包含 Electron RunAsNode/Worker、pnpm、原生模块和 agent presets 的显式消费者。
- 物理 runtime manifest 记录每个文件的消费者、大小和 SHA-256；afterPack 会拒绝缺失、额外或内容不一致的文件。
- Electron Builder 会从本地 workspace 中排除仅由 `devDependencies` 到达的 387 个 package name，并移除 map、类型声明、测试、示例、非运行时文档与 Windows x64 不可用的 arm64 原生资产。
- `package:dir`、Windows release build 和 CI 共同执行包体预算与 packaged Profile smoke；真实运行 DSH CLI、pnpm、Profile bundle 和物理 preset 路径。
- 新增同一 `win-unpacked` 的 ZIP 直写、默认 7z staged copy、实验性 7z 原地解压三方案构建；正式策略继续使用 ZIP，除非 7z 原地方案同时通过额外 10% 收益和恢复矩阵。
- 新增隔离 Windows benchmark、五次结果聚合、长路径组、内容寻址 tree manifest，以及 25%/50%/75% 强制终止和主程序锁定故障注入。
- 修复 packaged Profile 的 CommonJS 客户端包发现：`ClientModuleRegistry` 所需的 92 个 client bundle 文件（含桌面根包）由物理 runtime 清单投影，并为 `dsh-plugin-desktop` 建立受控 Profile junction。

## 安装性能与恢复

版本化 workflow 会在独立 `windows-latest` runner 上执行以下矩阵：

- v2.0.15、ZIP 候选、默认 7z、7z 原地方案各 5 次 80 字符路径 fresh install；
- v2.0.15 与 ZIP 候选各 5 次 180 字符长路径 fresh install；
- ZIP 候选的 25%/50%/75% 强杀和主程序锁定恢复；
- 只有完整旧版或完整新版 tree digest 合格，任何 missing/extra/changed 混合树都会失败。

发布要求 ZIP 候选相对 v2.0.15 同机中位数至少改善 40%，中位数不高于 90 秒，P95 不高于 120 秒。workflow 结果和 run URL 将在发布前补入本页与[同步台账](../upstream-sync.md)。

## 兼容与安全边界

- DeepSeek Harness 正式 package family 继续固定 `0.1.1-rc.2` 和子模块 `b150a551…`；新发布的 `0.1.2-alpha.2` 仅存在于 Git tag/npm `alpha`，不替代 `latest/next`。
- Better Sidebar 继续固定正式发布的 `0.17.1`；不使用超前 32 个提交的 `main` 快照。
- 桌面参考最新正式版仍为 `v2.0.4`，只作只读比较；根 README、品牌、下载链接和产品版本均由本仓库维护。
- 生产安装器继续使用 ZIP 直写，不启用实验性 7z 原地解压，也不放宽 legacy uninstaller code `2`。
- Windows 安装包如无受保护证书仍明确披露为 `NotSigned`；发布资产继续使用 SHA-256 和远端 digest 回读。
