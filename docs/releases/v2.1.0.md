# DSH Desktop v2.1.0

DSH Desktop v2.1.0 是一次产品能力大更新：在没有实时语音功能的 v2.0.16 基础上，首次把实时语音侧栏、Provider 凭据管理和语音 Agent 编排带入桌面产品。同时继续使用已审核的 DeepSeek Harness `0.1.1-rc.2` 和 Better Sidebar `0.17.1`。

## 主要更新

### 首次引入的实时语音能力

- 输入框新增语音按钮；用户可以在“设置 → 实时语音”中打开/关闭入口，并在侧栏查看连接、聆听、思考、播放和转写状态。
- 凭据由 DSH credentials 管理。Qwen 使用 Model Studio API Key，可选择共享 endpoint 或 Workspace 专属 endpoint；豆包使用语音应用 App ID 与 Access Token/Access Key。
- Qwen 级联模式（稳定）：实时 ASR → DSH Agent → Qwen TTS。它适合需要稳定文本 Agent、工具和审批链路的场景。
- Qwen 原生语音 Agent（实验）：普通对话由 Qwen Audio Realtime 直接回答；文件、终端、审批和项目上下文通过 DSH capability gateway 执行，再由 Qwen 生成原生音频。
- 豆包模式：实时 Seed-ASR 2 将语音转写给 DSH Agent，Agent 完成工具和文本回复，再使用 Seed-TTS 2 播放。
- Qwen Agent 桥接只保留为开发诊断路径，不在普通设置中作为第三个用户模式；已有内部值必须由用户明确改为级联或原生模式。

### 语音协议与安全边界

- Provider 原生音频使用 `voice.output.started`、`voice.output.audio`、`voice.output.done` 和 `voice.output.cancelled`；级联 TTS 继续使用 `tts.*`，两类状态不再混淆。
- 每个语音会话拥有独立的 response、Function Call、取消和 generation 状态；超时会在 10 秒内给出可诊断错误，不再无提示等待 180 秒。
- API Key、App ID 和 Access Key 不写入前端设置、URL 或诊断导出。Provider 只在活动会话期间接收麦克风音频，文件、终端和副作用仍由 DSH 权限与审批边界控制。

### 其他产品更新

- Vision 模型的 `inputModalities` 从目录、模型选择器贯通到 Host admission；明确 text-only 模型仍在上传附件前拒绝。
- Windows NSIS 不再把 `THIRD_PARTY_NOTICES.md` 当作需要用户同意的 EULA；第三方声明仍随包提供。安装器默认 per-user，选择 all-users 时保留一次标准 UAC。
- 产品与 Desktop package 版本同步升级到 `2.1.0`。
