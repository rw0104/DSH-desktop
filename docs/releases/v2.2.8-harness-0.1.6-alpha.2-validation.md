## Electron 兼容修复

前一候选的 Node 门禁通过，但实际 ASAR Host 被
`node-addon-require-builtin@0.1.6` 的 Electron 43.4.0 指纹校验拒绝，该候选未交付。
最终 app-boot patch 用公开同步模块钩子承接 ESM，复用官方路由、CommonJS Module
包装及 Worker 传播，保留 verify/enforce 和卸载恢复。条件导出缓存隔离经过真实
Node/Electron 回归，未修改或伪造 native addon。

另一个实际 Electron 问题是本地插件未导出 `package.json` 时丢失客户端。
client-modules 的无内部 Loader 回退现在使用官方 PluginPackages 元数据定位包；
局部回归先失败再通过，真实包内启停后的客户端和多会话探针都完成验收。

## 使用边界与未验收项

这是本地实验测试包。Windows 安装向导 GUI、真实 OS 目录选择、真实供应商音频，
以及 macOS/Linux 原生包未验收；隐藏 Renderer 或正常 EXE 启动不代替这些项目。
语音验证使用明确返回 409 的隔离 fixture，没有发起供应商音频请求。

升级前完全退出应用并备份 DSH home、user-data 及工作区。需要回滚时，把升级前完整
备份恢复到独立目录，再由匹配旧版本使用；不要让旧 runtime 直接复用升级后的数据。
V0/V3 原件保留不等于可以安全地让任意旧版本读取升级目录。

开发规划、日志、命令记录和截图依仓库边界保留在本地，不作为发布资产。

验收后已执行本地清理预览与 Apply，移除 13 个旧产物/展开目录/测试缓存，只保留
最新已验证安装器、对应校验和与 latest.yml。清理后再次核对安装器大小及 SHA-256/SHA-512。
