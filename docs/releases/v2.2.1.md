# DSH Desktop v2.2.1

修复 2.2.0 的实时语音按钮灰显和模型图片能力传输丢失，并为自定义供应商增加默认启用的图片能力自动识别。Harness 0.1.2-rc.1、Sidebar 0.18.0 与 Electron 43.4.0 保持不变。

自动识别不是服务端能力证明：明确的 `Vision` / `VL` 名称可用于推断，但中转服务实际支持可能不同。真实麦克风和服务商音频往返仍待实机验收；本记录不是正式 Release 公告。

## 实时语音

RC1 的凭据 API 已迁移到 `remote.credentials`。旧语音控制器仍读取已移除的 `connection.api.credentials`，并使用旧参数/返回值格式：即使 Host 已保存凭据且 ready，前端仍显示未配置、禁用按钮，保存新凭据也失败。

语音控制器改为使用生成的 RC1 Remote 类型、参数和 RemoteResult，显式等待 `remote` 父服务及 `remote.credentials`；读取失败会显示错误。回归覆盖“Host 有凭据而旧 connection.api 不存在”的按钮状态、设置和凭据保存，以及父服务注入声明。隔离打包启动拦截了最初候选中的父服务注入遗漏，该失败候选未交付。

## 自定义模型图片能力

模型目录虽然在 Host 返回 `inputModalities`，之前的下游补丁没有同步修改生成的 Host/Client Remote schema。字段经过 schema 解析后被剥除。本次同步两个生成产物，并增加经过真实 schema 的往返回归。

自定义 pi-ai/OpenAI-compatible 供应商默认自动识别图片输入，无需逐个勾选。适用于新获取的模型，也适用于已有但未声明 `input` 的模型：

1. “获取模型”保留供应商的输入能力字段；支持 `input`、`inputModalities`、`input_modalities`、`architecture.input_modalities` 和明确的图片输入布尔扩展字段。不会把输出图片能力当成图片输入能力。[OpenRouter 的输入/输出模态定义](https://openrouter.ai/docs/guides/overview/models)是其中一种支持的表示。
2. 仅有 ID 时，匹配当前安装的 pi-ai 模型目录中的同名 ID；目录之间有冲突则保持未确认，不按显示名冒充已知模型。
3. 目录不认识时，按 ID/显示名中具有词边界的 `Vision` / `VL` 标记推断，界面标明“名称推断”。例如 `DeepSeek-V4-Flash-Vision-Exp` 可以自动启用图片；`supervision` 不会被误匹配。
4. 没有证据、字段畸形或声明冲突时保留未确认状态。明确的仅文本声明优先于名称推断。

“设置 → 模型 → 自定义提供方 → 展开模型”默认显示“自动识别”。高级手动覆盖只用于修正接口限制或误判，正常使用不需要操作；已有的明确手动设置不会被获取模型覆盖。重新选择“自动识别”可移除手动覆盖。直接 DeepSeek 适配器仍使用自己的 `inputModalities` 配置合同。

能力字段及来源经过发现结果、生成的 Host/Client schema、编辑器采用和配置 schema 一路保留。识别不会后台上传测试图片、调用计费推理接口，或批量重写用户的 settings.yaml。

用户反馈截图里的视觉模型原配置只有 ID/名称；在增加自动识别之前，已针对指定单个模型补充输入声明，用户确认图片发送成功。这个本地配置修正与本次通用代码改动是两件事，不作为安装器对所有用户的批量能力覆盖。

验证包含真实 pi-ai 适配器向本地 HTTP 模拟端点发送图片 data URL，使用固定测试图片和测试凭据，不上传用户图片或调用真实模型计费接口。
