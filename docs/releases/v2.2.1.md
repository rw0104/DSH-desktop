# DSH Desktop v2.2.1

修复 2.2.0 的实时语音按钮灰显，以及模型图片能力在 Host/Client 传输过程中丢失的问题。Harness 0.1.2-rc.1、Sidebar 0.18.0 与 Electron 43.4.0 保持不变。

## 实时语音

RC1 的凭据 API 已迁移到 `remote.credentials`。旧语音控制器仍读取已移除的 `connection.api.credentials`，并使用旧参数/返回值格式：即使 Host 已保存凭据且 ready，前端仍显示未配置、禁用按钮，保存新凭据也失败。

语音控制器改为使用生成的 RC1 Remote 类型、参数和 RemoteResult，显式等待 `remote.credentials` 服务；读取失败会显示错误。回归覆盖“Host 有凭据而旧 connection.api 不存在”的按钮状态，以及设置和凭据保存。

## 自定义模型图片能力

模型目录虽然在 Host 返回 `inputModalities`，之前的下游补丁没有同步修改生成的 Host/Client Remote schema。字段经过 schema 解析后被剥除。本次同步两个生成产物，并增加经过真实 schema 的往返回归。

自定义 API 的模型列表可能只返回 ID/名称，不能据此保证模型支持图片。请在“设置 → 模型 → 对应提供方 → 展开对应模型”中开启“支持图片输入”并保存。pi-ai/OpenAI-compatible 路由使用每个模型的 `input: [text, image]`；直接 DeepSeek 适配器使用 `inputModalities`。未知模型不按名字猜测能力，明确 text-only 的限制保留。

用户反馈截图里的视觉模型原配置只有 ID/名称，缺少输入能力声明；该本地配置已针对用户指定的单个模型修正。此操作不会成为安装器对所有用户、所有模型的批量能力覆盖。

验证包含真实 pi-ai 适配器向本地 HTTP 模拟端点发送图片 data URL，使用固定测试图片和测试凭据，不上传用户图片或调用真实模型计费接口。
