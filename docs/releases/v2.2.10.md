# DSH Desktop 2.2.10

2.2.10 修复 DSH Desktop 2.2.9 在 Windows 上 `pwsh`、`glob`、`grep` 全部失效的问题。已安装 2.2.9 的用户需要安装 2.2.10 才能恢复这三个子进程工具。本版继续内置 Harness `0.1.6-alpha.2` 与 Better Sidebar `0.19.1`，不升级上游内核、不移动子模块 pin；Windows x64 正式 Release 仅在完整门禁通过并获得明确授权后发布，安装器未签名。

DSH Desktop 由社区独立维护，仓库与下载均在 [rw0104/DSH-desktop](https://github.com/rw0104/DSH-desktop)，与 DeepSeek 无隶属、授权或背书关系。

## 问题现象

- 在已安装的 2.2.9 中，`pwsh`（含 `echo hello`）约 0.5 秒失败并统一报错：
  `subprocess-local: Windows Job runner exited with exit code 0 before proving its managed range empty`。
- `glob` 与 `grep` 报 ripgrep provider failure，无法返回搜索结果。
- 不启动子进程的工具（读取、写入、编辑等）不受影响。

## 根因摘要

DSH Desktop 把 Host 运行在 Electron main 进程内，因此 `process.execPath` 指向 `DSH Desktop.exe` 而非 Node。上游 `@deepseek-ai/dsh-subprocess-local@0.1.6-alpha.2` 的 Windows Job runner 以 `[process.execPath, <runner 入口>]` 启动，且 runner 环境不含 `ELECTRON_RUN_AS_NODE`。于是 runner 被当作第二个完整桌面应用启动，执行到 `app.requestSingleInstanceLock()` 因已安装实例持锁而失败，随即 `app.quit()` 以退出码 0 结束、不回传任何 IPC 结果，父进程据此报"未能证明 managed range 为空"。`glob`/`grep` 把 ripgrep 二进制作为目标命令，同样经由该 Job runner 启动，因此一并失效。

## 受影响工具

`pwsh`、`glob`、`grep`。

## 修复方式

以两个最小、可审查的 Yarn Desktop_Patch（经根 `package.json` `resolutions` 应用于 `0.1.6-alpha.2`）修复，保持包族版本与子模块 pin 不变：

- **`@deepseek-ai/dsh-subprocess-local`（主修复）**：在 `launchWindowsJob` 的 runner 启动点，用 `withElectronRunAsNode(...)` 包裹 `runnerEnvironment(...)`。仅当 `process.versions.electron` 存在时，对 runner **自身进程**环境（大小写不敏感去重后）注入规范 `ELECTRON_RUN_AS_NODE='1'`，使 Electron 以纯 Node 模式执行 runner 入口。普通 Node 下为恒等变换，保持 alpha.2 行为；不修改 `runnerEnvironment` 本身，不污染 Linux 路径。
- **`@deepseek-ai/dsh-ptc-runtime-node`（同类调用点）**：在 `execute()` 启动子进程前，仅当同时满足"Host 为 Electron"与"解析出的解释器等于 `process.execPath`（即 `nodeExecutable` 取默认值）"时注入规范 `ELECTRON_RUN_AS_NODE='1'`。已显式配置 `nodeExecutable` 时不注入，保持 alpha.2 环境处理不变。

变量作用域隔离（关键正确性点）：注入的变量只作用于辅助进程自身；用户命令（Target_Command）的环境经独立的 IPC 载荷构造，不含该变量；Host 进程 `process.env` 前后不变。因此在 `pwsh` 中读取 `$env:ELECTRON_RUN_AS_NODE` 为空，用户在 shell 里启动的 Electron 类应用（如 VS Code）不会被误置为 Node 模式。

**Desktop_Adapter 现状保持不变（经审计确认无需改动）**：Windows ACL runner（`adaptWindowsAclExecution()` + trampoline）、终端会话清除 `ELECTRON_RUN_AS_NODE`、pnpm 与 Profile 包管理器的既有 RunAsNode 设置均保持原行为。

### 审计结论摘要

对已安装 alpha.2 `@deepseek-ai/dsh-*` 包族产物与 Desktop 自有代码中所有"以 `process.execPath` 充当 Node 解释器"的调用点做了全量审计：**受影响 2 处**（Windows Job runner、`ptc-runtime-node` 默认解释器路径），均已由上述两个 Desktop_Patch 修复；其余调用点为**不受影响**（例如目录选择器在 Windows 组合下不可达、ripgrep 解析自身不属 execPath-as-Node）或**已适配**（ACL runner、终端清除、pnpm/Profile 包管理器等已显式处理）。`dsh-community-market/` 未出现任何子进程/execPath 调用点，Community Market 在线源回放不适用。

## 验证摘要

- **单元与属性测试**：注入逻辑的示例/边界单元测试，加 5 项属性（Electron 下恰含规范变量、普通 Node 恒等、变量仅作用于 runner 自身、非零退出码透传、已配置 `nodeExecutable` 时保持原行为），每项 ≥100 次随机迭代通过。
- **真实 Electron 回归**（Electron 43.4.0 / Node 24.18.1，隔离 `--user-data-dir` + 无头运行）：先在未打 patch 行为下复现原始失败（错误串与现场逐字一致，`pwsh` 与 ripgrep 同源），再验证修复后 `pwsh echo hello` 返回退出码 0 与 `hello`、非零退出码透传、Target_Command 环境不含 `ELECTRON_RUN_AS_NODE`、Host `process.env` 未变、`glob` 命中预置文件、`grep` 命中预置文本与行、无匹配返回空结果不报错。
- **打包冒烟**（对本次构建产物显式启动，非已安装应用，隔离 `DSH_HOME`/user-data/工作目录）：`pwsh echo hello`、`glob`、`grep` 均在 30 秒内恢复；读取打包产物确认 `RunAsNode` fuse 处于启用状态，本修复所依赖的 Electron-as-Node 能力成立。

## 已知限制

- Desktop_Patch 作用于 npm 发布的编译后 JavaScript，属行级 patch，在上游包族升级时必然需要重放或移除（见下上游迁移步骤）。
- 本方案依赖打包应用启用 `RunAsNode` fuse；本版已在打包产物中确认其启用。
- `glob`/`grep` 的恢复依赖 Windows Job runner 的主修复，二者同源。
- 实际 `v2.2.10` 的打 tag、GitHub Release 发布与覆盖安装需另行明确授权，不随本版本递增自动执行。

## 上游后续迁移步骤

- **F1（上游迁移）**：上游最新版本 `dsh-v0.2.0-rc.1` 仍以 `process.execPath` 启动 Windows Job runner 且不注入 `ELECTRON_RUN_AS_NODE`，缺陷未修复。因此保持 `@deepseek-ai/dsh-*` 于 `0.1.6-alpha.2`、子模块 pin 不变并保留本次 Desktop_Patch。待上游在 `subprocess-local` 中注入 `ELECTRON_RUN_AS_NODE`（或使其感知 Electron 运行形态）后，再按完整包族原子升级并移除本 patch，子模块 pin 更新单独提交。
- **F2（上游问题报告）**：向 `deepseek-ai/deepseek-harness` 报告 Electron Host 下的 execPath-as-Node 缺陷并附最小复现。

上游核查明细记录在 [upstream 同步账本](../upstream-sync.md)。上一版发布说明见 [v2.2.9](v2.2.9.md)。
